# ضریب مصرفی per-user برای پنل پاسارگارد (PasarGuard)

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

به هر کاربر پنل پاسارگارد یک **ضریب مصرف جداگانه** بدهید — با پنل وب فارسی و بدون نصب هیچ وابستگی اضافه.

> **English:** Per-user usage coefficient for PasarGuard (Marzban fork) panels — Persian web UI + CLI, Python stdlib only. Set a multiplier per user; the panel itself shows and enforces the multiplied usage.

## ✨ امکانات

- 🖥 **پنل وب فارسی/RTL** با آمار زنده، نوار پیشرفت و ویرایش ضریب درجا
- 🔢 ضریب از لحظه ثبت به بعد اعمال می‌شود — **مصرف قبلی کاربر دست‌نخورده می‌ماند**
- 👁 در مود پیش‌فرض (`native`) مصرف ضریبی مستقیم در خود پاسارگارد دیده می‌شود و خود پنل سر حد قطع می‌کند
- 🔄 ریست مصرف ماهانه، افزایش حجم توسط ادمین و حذف ضریب — همه خودکار هندل می‌شوند
- 🧮 مکمل ضریبِ per-node خود پاسارگارد (که فقط روی همه کاربرانِ یک نود اثر دارد)
- 📦 فقط Python 3.8+ — بدون `pip install`

## 🚀 نصب سریع (روی سرور پنل)

```bash
sudo bash <(curl -sL https://raw.githubusercontent.com/behymin12345-hash/pasarguard-coefficient/main/install.sh)
```

اسکریپت نصب: فایل‌ها را در `/opt/pg-coef` می‌گذارد، کانفیگ را می‌پرسد (یا کانتینر دیتابیس را خودش تشخیص می‌دهد)، سرویس systemd را می‌سازد و آدرس + رمز پنل را چاپ می‌کند.

### نصب دستی

```bash
git clone https://github.com/behymin12345-hash/pasarguard-coefficient.git /opt/pg-coef
cd /opt/pg-coef
cp config.example.json config.json
nano config.json          # panel_url + احراز هویت + web_password را پر کنید
python3 pg_panel.py       # یا سرویس systemd بسازید (پایین README)
```

**ویندوز هم پشتیبانی می‌شود:** فقط `python pg_panel.py` اجرا کنید.

## ⚙️ کانفیگ (config.json)

| کلید | توضیح |
|------|-------|
| `panel_url` | آدرس پنل پاسارگارد |
| `api_key` یا `admin_username`/`admin_password` | احراز هویت ادمین (API Key از داخل پنل: تنظیمات → API Keys) |
| `mode` | `native` (پیشنهادی) / `disable` / `limit` / `report` |
| `db_container` | فقط برای مود native: نام کانتینر دیتابیس پنل (مثل `pasarguard-timescaledb-1`) |
| `web_password` / `web_port` | رمز و پورت پنل وب ضریب (پیش‌فرض 9012) |
| `interval_seconds` | فاصله همگام‌سازی (پیش‌فرض ۶۰) |
| `default_coefficient` | ضریب پیش‌فرض کاربرانِ بدون ضریب (۱ = خاموش) |
| `verify_tls` | اگر پنل SSL سلف‌ساین دارد: `false` |

---

این اسکریپت به شما اجازه می‌دهد برای **هر کاربر به‌صورت جداگانه یک ضریب مصرف** تعیین کنید، بدون اینکه حجم (data_limit) کاربر کم شود.

## فرمول

```
مصرف مؤثر = مبنا + مصرفِ بعد از ثبت ضریب × ضریب
```

ضریب **از لحظه ثبت به بعد** اعمال می‌شود؛ مصرفِ قبلی کاربر دست‌نخورده می‌ماند.

| ضریب | معنی | کاربر با حجم ۱۰ گیگ |
|------|------|---------------------|
| `2` | مصرف جدیدش دوبرابر حساب می‌شود | عملاً نصف گیگِ باقی‌مانده را می‌خورد |
| `1.5` | مصرف جدید ۱.۵ برابر | عملاً ~۶.۶ گیگ باقی‌مانده |
| `1` | بدون ضریب (حذف ضریب) | همان ۱۰ گیگ |
| `0.5` | مصرف جدید نصف حساب می‌شود (بخشندگی) | عملاً تا ۲۰ گیگ می‌خورد |

## چرا اسکریپت؟

در سورس پنل پاسارگارد، «ضریب مصرف» فقط به‌صورت **per-node** وجود دارد (`usage_coefficient` روی هر نود؛ مصرفِ همه کاربرانِ آن نود ضرب می‌شود). ضریب **per-user** در پنل وجود ندارد و `used_traffic` از طریق API قابل نوشتن نیست.

مود پیش‌فرض `native` این خلأ را کامل می‌کند: مصرف ضریبی مستقیم در دیتابیس پنل نوشته می‌شود (شمارش مصرف پاسارگارد انباشتی است، پس نوشتن مطلق پایدار می‌ماند) — نتیجه: پنل خودش مصرف ×ضریب را نمایش می‌دهد و خودش سر حد قطع می‌کند.

## پیش‌نیاز

- Python 3.8 به بالا (روی ویندوز یا لینوکس؛ فقط کتابخانه استاندارد — هیچ `pip install` لازم نیست)
- دسترسی ادمین به پنل (یوزر/پسورد ادمین یا یک API Key از داخل پنل)
- برای مود `native`: اجرا روی همان سرور پنل با دسترسی docker (برای نوشتن در دیتابیس)

## راه‌اندازی (یک بار)

۱. `config.json` کنار اسکریپت را پر کنید (نمونه کامل: `config.example.json`):

```json
{
  "panel_url": "https://panel.example.com",
  "admin_username": "admin",
  "admin_password": "••••",
  "api_key": "",
  "mode": "native",
  "db_container": "pasarguard-timescaledb-1",
  "auto_reenable": true,
  "interval_seconds": 60,
  "default_coefficient": 1.0,
  "timeout_seconds": 20,
  "verify_tls": true,
  "web_password": "یک-رمز-برای-پنل-وب",
  "web_port": 9012
}
```

- به‌جای پسورد می‌توانید فقط `api_key` بگذارید (داخل پنل: تنظیمات → API Keys). اگر هر دو خالی باشند اسکریپت خطا می‌دهد.
- اگر SSL پنل سلف‌ساین است: `"verify_tls": false`
- `db_container` را خالی بگذارید تا مود native غیرفعال شود (مودهای دیگر نیازی به آن ندارند).

۲. تست اتصال:

```
python pg_coef.py login-test
```

## پنل وب (pg_panel.py)

اسکریپت یه رابط وب فارسی/RTL هم دارد:

```
python3 pg_panel.py
```

- تنظیماتش در همان `config.json` است: `web_password` (الزامی) و `web_port` (پیش‌فرض 9012)
- همگام‌سازی خودکار در پس‌زمینه + دکمه دستی «🔄 همگام‌سازی»
- لیست همه کاربران با مصرف واقعی/مؤثر، نوار پیشرفت، وضعیت، و ویرایش ضریب همان‌جا
- تغییر مود / ضریب پیش‌فرض / فاصله sync / رمز پنل از خود UI
- احراز هویت با توکن؛ رمز اشتباه با تأخیر رد می‌شود

نکته امنیتی: پنل وب روی HTTP ساده سرو می‌شود؛ پورتش را فقط جایی که لازم است باز نگه دارید یا از تانل SSH استفاده کنید.

## دستورات

| فرمان | کار |
|-------|-----|
| `python pg_coef.py login-test` | تست اتصال و احراز هویت |
| `python pg_coef.py set <user> <k>` | ثبت ضریب برای یک کاربر — مثال: `set ali 2` |
| `python pg_coef.py set-all <k>` | ثبت یک ضریب برای همه کاربران پنل |
| `python pg_coef.py set-default <k>` | ضریب پیش‌فرض برای کاربرانِ بدون ضریب (⚠ روی همه پنل اثر دارد) |
| `python pg_coef.py remove <user>` | حذف ضریب یک کاربر |
| `python pg_coef.py remove-all` | پاک کردن همه ضریب‌ها |
| `python pg_coef.py list` | نمایش ضریب‌های ثبت‌شده |
| `python pg_coef.py sync` | **یک دور اعمال** روی پنل |
| `python pg_coef.py run` | **پایش دائمی** (هر `interval_seconds` ثانیه یک دور) |
| `python pg_coef.py report` | جدول مصرف مؤثر همه کاربران (بدون تغییر چیزی) |
| `python pg_coef.py node-list` | نودها + ضریب native خود پنل |
| `python pg_coef.py node-set <name|id> <k>` | تنظیم ضریب native یک نود |

فلگ‌های عمومی (قبل یا بعد از هر فرمان): `--config`، `--file`، `--url`، `--username`، `--password`، `--api-key`، `--mode`، `--interval`، `--quiet`

## مودها — چه چیزی به چه شکلی اعمال می‌شود

### مود `native` (پیشنهادی) — همه‌چیز داخل خود پاسارگارد

- مصرف ضرب‌شده **مستقیم در دیتابیس پاسارگارد** نوشته می‌شود؛ پنل خودش `×ضریب` را نمایش می‌دهد (هم در داشبورد ادمین، هم صفحه اشتراک کاربر) و خودش سر حد `limited` می‌کند.
- حجم (`data_limit`) هیچ‌وقت دست نمی‌خورد؛ ریست مصرف ماهانه هم خودکار هندل می‌شود (مبنا دوباره از صفر ثبت می‌شود).
- نیاز به `db_container` دارد و باید روی خود سرور پنل اجرا شود. ⚠ قبل از استفاده اول یک بکاپ از دیتابیس بگیرید.
- ضریب کمتر از ۱ (بخشندگی) در این مود یعنی مصرف نمایشیِ همه (قبلی + جدید) ÷ k می‌شود — به نفع کاربر.

### مود `disable` — «از حجمش کم نشه»

- **حجم و مصرف نمایشی پنل هیچ‌وقت دست نمی‌خورد** — ضریب برای کاربر نامرئی است.
- اسکریپت هر دور چک می‌کند: اگر «مبنا + مصرف جدید × ضریب ≥ حجم» شد، کاربر را با endpoint مخصوص قطع (`disabled`) می‌کند و در فایل `coefficients.json` علامت می‌زند که «این قطع مال من بود».
- تا وقتی مصرف ریست شود یا ادمین حجم را زیاد کند یا ضریب کم شود، کاربر خودکار وصل می‌شود (با `auto_reenable`).
- فقط مصرف بین دو چک دیر اعمال می‌شود (حداکثر به اندازه `interval_seconds`). پیش‌فرض ۶۰ ثانیه است.

### مود `limit` — سقف نمایشی پویا

- اسکریپت `data_limit` را پویا تنظیم می‌کند (`V − (k−1)×مصرفِ جدید`) تا **خود پنل** دقیقاً سر ضریب کاربر را `limited` کند — حتی اگر اسکریپت خاموش شود.
- در عوض حجم نمایشی کاربر در صفحه اشتراک به‌مرور تغییر می‌کند. اگر ظاهر صفحه کاربر مهم است، از این مود استفاده نکنید.
- اگر ادمین دستی حجم را عوض کند، اسکریپت می‌فهمد و مبنای جدید را می‌گیرد.
- کاربر با ضریب کمتر از ۱ در **هر مودی** خودکار با مکانیزم limit اجرا می‌شود (حجمش به `V/k` بالا برده می‌شود).

### مود `report`

هیچ چیزی را تغییر نمی‌دهد؛ فقط جدول مصرف مؤثر را نشان می‌دهد.

> در همه مودها، ضریب از لحظه ثبت به بعد اعمال می‌شود (مصرف قبلی ×ضریب نمی‌شود). تغییر ضریب هم مبنا را دوباره ثبت می‌کند.

## رفتارهای خودکار

- **ریست مصرف (ماهانه یا دستی):** مصرف صفر می‌شود → مبنا از نو ثبت و کاربر قطع‌شده وصل می‌شود.
- **افزایش حجم توسط ادمین در پنل:** بلافاصله در دور بعد لحاظ می‌شود؛ هیچ چیزی snapshot نمی‌شود.
- **حذف ضریب:** در دور بعد `sync`، مصرف واقعی و حجم پایه به پنل برمی‌گردد و کاربر قطع‌شده وصل می‌شود.
- **تغییر ضریب:** فقط `set` جدید بزنید؛ مبنا از همان لحظه دوباره ثبت می‌شود.

## اگر اسکریپت خاموش شود؟

- مود `native`: **هیچ مشکلی نیست** — نمایش و قطعِ ضریبی روی خود پنل باقی می‌ماند؛ فقط ریست‌های جدید تا برگشتن اسکریپت با ضریب حساب نمی‌شوند.
- مود `disable`: کنترل مصرف متوقف می‌شود («fail-open» — امن‌تر از قطع اشتباهی). مود `limit`: محدودیت قبلی پنل باقی می‌ماند ولی کمی شُل‌تر. پس:

- روی سروری که همیشه روشن است سرویس systemd را بالا بیاورید (نصب‌کننده خودش می‌سازد) یا `python pg_coef.py run` را دائمی اجرا کنید.

**ویندوز (Task Scheduler):**
```
schtasks /create /tn "pg_coef" /tr "python C:\pg\pg_coef.py run" /sc onstart /ru SYSTEM
```

**لینوکس (systemd):** فایل `/etc/systemd/system/pg-coef.service`:
```ini
[Unit]
Description=PasarGuard per-user usage coefficient
After=network-online.target

[Service]
ExecStart=/usr/bin/python3 /opt/pg/pg_coef.py run
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```
سپس: `systemctl enable --now pg-coef`

> فایل `coefficients.json` (ضریب‌ها + وضعیت) را موقع انتقال سرور/اسکریپت همراه ببرید؛ از دست رفتنش فقط یعنی چک دوباره از صفر و reconnect کاربرانِ قطع‌شده، نه خرابی.

## ضریب native نودها

اگر کاربران‌تان روی نودهای جدا هستند، می‌توانید از ضریب خودِ پنل هم استفاده کنید (بدون نیاز به sync دائمی؛ مستقیم موقع ثبت مصرف ضرب می‌شود):

```
python pg_coef.py node-list
python pg_coef.py node-set de-node 2
```

این ضریب روی **همه کاربرانِ آن نود** اثر می‌گذارد (per-node است، نه per-user).

## تست بدون پنل واقعی

```
python tests/run_tests.py

```

یک پنل شبیه‌سازی‌شده بالا می‌آورد و همه سناریوها را چک می‌کند: مبنا (ضریب فقط روی مصرف جدید)، قطع/وصل، ریست، بخشندگی، مودهای limit و disable، حذف ضریب، ضریب پیش‌فرض، ضریب نود و API های پنل وب.

## سوالات متداول

**کاربر می‌پرسد چرا قطع شدم در حالی که حجمش باقی است!**
در مود `disable` کاربر مصرف واقعی و حجم کامل را می‌بیند و ضریب برایش نامرئی است. برای اینکه کاربر «مصرف ضریبی» را در صفحه‌اش ببینید، مود `native` را انتخاب کنید (پیش‌فرض نصب‌کننده).

**ضریب برای یک کاربر قاطی نشود با تغییرات ادمین؟**
تغییرات ادمین (حجم، ریست، وضعیت) همیشه مبنای محاسبه دور بعد است؛ اسکریپت چیزی را کپی/قفل نمی‌کند.

**مصرف قبلی کاربر هم ضرب می‌شود؟**
نه — موقع ثبت ضریب، مصرف فعلی به‌عنوان مبنا ثبت می‌شود و فقط مصرف بعد از آن ضرب می‌شود. تغییر ضریب هم مبنا را دوباره ثبت می‌کند.

**امنیت فایل‌ها؟** `config.json` (پسورد/کلید) و `coefficients.json` (وضعیت) را پابلیک نکنید و دسترسی فایل را محدود کنید (`chmod 600`). هر دو در `.gitignore` ریپو هستند.

**چند ادمین؟** اسکریپت با هر ادمینی که در config باشد کار می‌کند؛ فقط باید دسترسی ویرایش آن کاربران را داشته باشد.

**امنیت:** `config.json` شامل پسورد/API Key ادمین است — دسترسی فایل را محدود کنید و آن را جایی پابلیک نکنید.
